## 实现边界

新增egtool.student_portal是独立的学生网页适配器：由固定程序预加载eg-student-feedback、eg-authenticity-anchor、eg-report-feedback及评分规则，通过教师配置的HTTPS文本模型接口执行固定反馈任务。它不是OpenClaw原生Agent执行器；本轮没有改动默认Gateway或重新部署旧教学profile。

学生只得到课程匿名编号和个人高熵口令。服务端保存口令哈希，以HttpOnly/SameSite=Strict的会话Cookie鉴权，正式模式额外要求Secure。账号归属、会话读写清除、限流、并发和Schema校验在模型之外执行。每次模型请求只含当前本人材料与固定规则，不发送课程账号、其他报告、聊天历史或教师端规则。学生不能选择Agent、模型、接口地址、文件路径、工具、配置或系统提示；未知字段拒绝。

不注册或执行任何模型工具，拒绝模型返回的tool_calls/function_call。网页不代理Gateway/WebSocket/通用API，不存在教师端、执行、文件、配置和全局会话列表路由。页面通过textContent显示反馈，输入HTML不执行。公开教师端源码仍可阅读，这与教师服务权限不同；源码公开无法阻止学生自行改写自己的本地副本，因此本地自行运行不能当成受控课程服务证明。

新增midterm-submission/gate/feedback Schema仅用于期中模式。egtool.midterm.material_gate检查正文与隐私，记录草图、证据卡缺席，照常返回eligible并要求全部六维；字数不足、书目不齐、来源未核、缺修订记录均不阻断。原teacher-intake和legacy材料门槛保留，默认旧流程不变。来源未核明确标注，不能自动认定文献研究类型或材料真实性。地域与隐私扫描是初筛，不是语义正确性或完全去标识的证明。

## 本机合成演示

使用Python3.12或以上。在仓库目录执行，下列PRIVATE_DIR须换成仓库外的新建私有路径，不能覆盖既有目录。

```bash
python3 -m egtool.student_portal provision --out PRIVATE_DIR
python3 -m egtool.student_portal serve --demo --roster PRIVATE_DIR/roster.json --origin http://127.0.0.1:18894 --port 18894
```

provision生成66个随机口令，roster.json与individual-access.csv权限为600，目录为700。后者含明文访问口令，只由教师逐人私发，不进入GitHub或学生统一下载包。本次产生的演示凭证只供本机合成测试，没有作为正式凭证发放。demo只允许127.0.0.1的HTTP地址，明确标记未调用模型，不接受将演示后端冒充正式模式。

## 正式开放还缺什么

1. 教师选定常在线主机。优先询问校内已有资源；教师电脑可先试点，但睡眠、断网或关机会中断服务。目前没有服务器或域名，不需要先买域名。可使用校内提供的HTTPS子域名。不能把GitHub Pages当作本Python服务主机，也不能向全班共享默认Gateway管理凭证。
2. 选定模型服务商和模型，核实该服务商对无工具Chat Completions、JSON输出和上述请求参数的支持、预算及数据处理政策。不得自动复用默认OpenClaw中的认证。密钥只在服务端环境或密钥管理中设置EG_MODEL_URL、EG_MODEL_ID、EG_MODEL_KEY，前端无密钥；URL必须HTTPS，不跟随重定向。
3. 在独立低权限系统账号/容器中运行，仅挂载只读代码与必要的私有账号文件，不挂载教师资料、家庭目录、Docker socket或旧OpenClaw状态。只让服务账号访问批准的模型域名，使用系统防火墙/容器策略限制其他网络出口。文件/命令路由不存在不等于宿主进程具备OS级隔离。
4. 在同一HTTPS域名反向代理到127.0.0.1:18894，保留正确Host；只放行本学生服务，不转发其他Gateway端口。设置请求大小不超过180KB、连接/请求速率上限、模型最长等待约180秒及足够读取超时；不缓存、不记录正文/Cookie/凭证。应用要求精确Origin/Host，不信任转发头来授予身份。正式模式只接受HTTPS来源；应用自身始终只监听回环地址。
5. 用真实供应商和至少两个测试账号实测登录、模型六维输出、草图/证据卡四种有无组合、提示注入、越权、Cookie、刷新/退出、限流与错误恢复。先由3至5名自愿试用者验证操作和专业反馈，再做目标网络下的多人试验与成本核算。专业判断由教师验收，不由结构校验代替。
6. 核实报告/日志/内存/供应商侧留存和删除方式，再向学生告知。完成问卷星两个独立上传题目和访问权限检查，填写教程中的URL、截止时间、支持渠道及数据政策，然后发布个人凭证。没有这些实测结果不发布“全班已开放”。

正式运行示例（参数值由教师配置，示例没有真实地址或密钥）：

```bash
python3 -m egtool.student_portal serve --roster PRIVATE_DIR/roster.json --origin https://TEACHER_CONFIRMED_HOST --port 18894 --provider-approved
```

--provider-approved仅表示教师已核查并授权所选供应商的数据处理，不是程序自动完成验收的证据。生产模型每账号最多20次（本服务进程生命周期），同账号间隔20秒；全局4个模型请求并行，满额返回429，无自动重试。这些限额不代表66路并发能力。进程重启会清空会话/反馈/临时配额；凭证需要撤销时更新私有roster后重启，旧会话同时失效。

## 数据、版本与成本

服务不将报告正文写入磁盘，仅在内存保存当前反馈和片段引用，会话4小时到期，空闲时仍每约0.5秒清理。清除/退出会删除当前记录；生成期间清除会使旧响应失效，但不等于取消已发给供应商的请求。浏览器显示、系统交换内存、进程故障转储和供应商日志另需部署方控制。正式材料只在问卷星私有入口提交；身份映射和个别访问口令由教师私存。

GitHub公开仓库只能分发代码。让66人下载并自行运行，会将安装支持、模型密钥、预算和合规判断分散给每人，不能自动满足统一受控权限要求。低服务器支出不一定是最低总成本。建议先用已有校内资源或教师机小规模试点，按实际模型用量决定后续投入。模型费可按“66×每人轮数×（平均输入tokens×输入单价＋平均输出tokens×输出单价）”估算，价格单位需与服务商计费单位一致；本轮没有真实用量，不能给出可靠金额。

合并PR后仍需显式执行上述部署和验收，不触发自动生产发布。旧main基线、标签和历史归档保留，回退代码使用Git版本；不拿新草案反向恢复任何唯一正式原件。
