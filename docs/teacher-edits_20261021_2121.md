# 教师修改反馈与追溯

教师可改写、补充或撤回问题，也可调整维度判断。程序保留原模型输出，修改稿使用新校验值。修改稿需要重新进行教师端模型复核，再由教师完成本轮终审。上一版批准记录不能用于修改稿。

## 创建修改记录

先针对当前报告、材料核查、反馈和模型复核生成模板：

```bash
python3 -m egtool edit-template \
  --submission /PRIVATE/submission.json --intake /PRIVATE/intake.json \
  --feedback /PRIVATE/feedback.json --teacher-review /PRIVATE/review.json \
  --out /PRIVATE/edit-plan-NEW.json
```

模板尚未填写教师信息或修改动作。教师填写自己的匿名编号、带时区的实际时间和逐项理由。T000只用于合成技术测试。每项动作使用以下一种操作：

| 操作 | 用途 |
|---|---|
| replace_issue | 改写问题内容，保留原编号与修改前内容 |
| add_issue | 新增问题，使用本次历史中未使用过的新编号 |
| remove_issue | 撤回问题，保留原文和撤回理由 |
| set_dimension | 更新判断依据、等级、状态或关联任务，保持评价与问题清单一致 |

修改计划绑定当前报告、反馈和模型复核的校验值。不能通过修改计划替换报告原文、身份、来源或终审记录。修改引句仍须与原报告一致。

```bash
python3 -m egtool apply-edits \
  --submission /PRIVATE/submission.json --intake /PRIVATE/intake.json \
  --feedback /PRIVATE/feedback.json --teacher-review /PRIVATE/review.json \
  --plan /PRIVATE/edit-plan-NEW.json --out /PRIVATE/edited-NEW
```

输出包含原反馈、原复核、修改稿、修改记录和阅读摘要。记录保存每次修改前后的完整反馈、动作、理由、教师编号、时间及前一版本的校验值。再次修改同一稿件时，程序读取已有记录继续追加。已经撤回的编号不能重新用于另一问题。

## 重新复核与终审

将feedback-amended.json交给教师端模型重新复核；原复核绑定旧反馈，程序会拒绝沿用。随后用修改稿、新复核和修改记录生成终审模板：

```bash
python3 -m egtool final-template \
  --submission /PRIVATE/submission.json --intake /PRIVATE/intake.json \
  --feedback /PRIVATE/edited-NEW/feedback-amended.json \
  --teacher-review /PRIVATE/review-amended.json \
  --edit-ledger /PRIVATE/edited-NEW/edit-ledger.json \
  --out /PRIVATE/final-amended-NEW.json
```

新模板保持未终审和未批准状态。教师逐项确认后，使用release生成本地发放包；修改记录随终审副本一起归档。修改稿带有追溯编号，缺少对应记录时不能生成终审模板或显示已采用状态。记录紧邻修改稿时可自动找到，移动文件后应显式提供--edit-ledger。

## 多维关联同一任务

同一实质问题只保留一项学生任务。其他相关维度使用related_issue_ids引用已有任务编号，并说明本维判断。例如，推理链中的绝对化结论同时影响不确定性评价时，两个维度可以分别给出依据，学生只需回应一项对应任务。程序检查关联编号存在且属于另一维度。

合成连续测试保留模型原响应；若原依据已经明确写出已有任务编号，程序只补充对应的关联字段，并另存转换记录。转换不改动评价、任务或文本，也不产生教师批准。

本轮在1.1.0协议中增加可选关联与追溯字段。使用新功能时应同步更新Schema、校验器和工作区资源；旧校验器会拒绝不认识的字段。旧反馈不含这些字段时仍可由新程序读取。
